# 教训与已验证决策 — UDES1GN

> 增量记录，不删历史。踩过的坑、已验证的决策、不要重复犯的错。

## 已验证决策

- **2026-06-24｜初始版不拆前后端**：deck 原设想 Next.js + NestJS 双服务。评估后定为单 Next.js 全栈——单台 HK 服务器、单区域、目标只是验证有没有人用，双服务是无谓的双倍运维成本。NestJS 等真有后端复杂度再拆。
- **2026-06-24｜License = AGPL-3.0**：这是"别人可自托管的平台型"项目，AGPL 防止被闭源 SaaS 套壳，是社区项目标准选择。仓库初始即带 AGPL LICENSE。
- **2026-06-24｜范围砍治理**：中国版/国际版双线、声誉/加权投票、OAuth、通知、贡献治理流程全部移出初始版。理由：这些是治理/运营复杂度而非技术瓶颈，0 用户阶段做这些是空转。

## v1 参考与分歧（2026-06-24）

- 用户 2024-08 做过一版 v1（`~/Downloads/udes1gn-master`），详见 [`v1-reference.md`](./v1-reference.md)。v1 只做了账号脚手架（login/register/forgetPS/setting/user），**核心提案投票状态机完全没做**，未上线。
- **用户明确喜欢 v1 的 UI**（Apple 风极简白）→ v2 沿用其设计基线（配色/圆角/字体/深色模式/slogan「这块地盘由你决定」），见 v1-reference §设计基线。
- **认证模型分歧 [待定]**：v1 = localStorage token + 独立后端；v2 计划 = 单进程全栈 + Auth.js 服务端 session。两者冲突，v2 采用后者（更安全、单服务器更省），v1 认证逻辑不续用。
- **样式 = 全面 tailwindcss（2026-06-24 定）**：v1 混用 scss + styled-components + tailwind 三套，且自制了 `flexCC`/`flexB` 等 flex 工具类。v2 **全面用 tailwindcss，摈弃所有 v1 自制工具类**；仅保留极少量全局 scss 承载配色 CSS 变量与深色模式。class 对照表见 [`v1-reference.md`](./v1-reference.md)。
- **首版多语言 = 中英 + DB 驱动后台可管（2026-06-24 定）**：用户拍板首版上中英双语，且要后台能管理语言/文案，数据结构为未来任意语言 + 用户定制化多语言留好（对标 x.com）。不沿用 v1 的静态 json（改语言要改代码、给不了运营自助）。分层关键：**界面文案**（首版做，DB+后台）与**用户内容多语言**（留 roadmap）两条线分开。完整方案见 [`implementation.md`](./implementation.md) §9。
  - ⚠️ 注意区分：**多语言 ≠ 多区域**。早先砍掉的"中国版/国际版双线"指的是区域/法律分区，不是语言；多语言照做。
