# 业务领域 — UDES1GN 友定

## 定位

用户共创、参与决策的社区平台。区别于普通论坛/许愿池的唯一点：**提案有公开的决策状态机**——用户能看到自己的投票如何改变了产品走向。

## 核心概念

| 概念 | 说明 |
|---|---|
| **提案 Proposal** | 一条待决策的需求/设计。不是普通帖子，是"一件等着被表决和推进的事"。含标题、描述、分类、状态。 |
| **投票 Vote** | 对提案的赞成表态。**1 人 1 票**，可取消。赞成数 = 提案排序权重。 |
| **评论 Comment** | 挂在提案下的讨论。 |
| **状态机 Status** | 提案的生命周期，仅管理员可推进。 |
| **举报 Report** | 用户对提案/评论的举报，进管理员审核队列。 |
| **角色 Role** | `USER`（普通）/ `ADMIN`（管理员，可改状态/审核/封禁）。初始版不设中间角色。 |
| **语言 Locale** | 一种界面语言（BCP-47 code，如 `zh`/`en`）。后台可增删/启停，有一个默认兜底语言。首版上中英。 |
| **文案 Translation** | 一条界面文案 = `(namespace, key, localeCode) → value`，DB 存储、后台可编辑。区别于**用户内容**（提案/评论正文，首版按作者语言单语存储）。 |

## 提案状态机（命门）

```
收集中 COLLECTING
   ├─→ 已采纳 ADOPTED ──→ 开发中 IN_PROGRESS ──→ 已上线 SHIPPED
   └─→ 已否决 REJECTED
```

- 新提案默认 `COLLECTING`。
- 状态只能由 `ADMIN` 推进；普通用户只读。
- 状态变更应可追（初始版至少记录 `updatedAt`；后续可加变更日志）。
- **为什么是命门**：没有可见的状态流转，"共创/决策"就是空话，用户投完票石沉大海就会流失。

## 业务规则

- 1 用户对 1 提案最多 1 票（数据库 `@@unique([proposalId, userId])` 强约束）。
- 被封禁用户（`bannedAt` 非空）不能提案/投票/评论。
- 被隐藏内容（`hiddenAt` 非空）对普通用户不可见，管理员可见。
- 提案作者不可删除已被采纳/上线的提案（保留决策记录）。

## 暂不属于本领域（终态设想，初始版外）

跨国法律并集、中国版/国际版分区、声誉/加权投票、代币、用户自治平台本身的元治理。
